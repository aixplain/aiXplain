# بيانات التشغيل (Run metadata)

ترسل تشغيلات الوكلاء عبر aiXplain SDK كائن `metaData` مرفقًا بطلبك. هذه الصفحة هي
الإفصاح الكامل عمّا يحتويه هذا الكائن، ولماذا يُجمع، وإلى أين يُرسل، وماذا يحدث عند
فشل الاستعلام الذي يقف خلفه. القائمة الدقيقة في قسم «أي الاستدعاءات ترسلها» أدناه —
وتحديدًا: تشغيلات v2 التي تمرّ عبر جلسة لا تحمله.

يُبنى `metaData` بواسطة
[`aixplain.utils.user_info_utils.build_run_metadata()`](../aixplain/utils/user_info_utils.py).
وهو غير مرتبط ببيانات التشغيل التي تُرسل في الترويسات فقط (`x-session-id` و`x-agent`)
والتي تصدرها موارد v2 لأغراض التتبع.

---

## ما الذي يُرسل

| مفتاح `metaData` | النوع | المصدر | مثال |
|---|---|---|---|
| `userAgent` | نص | ثابت `"sdk"` | `"sdk"` |
| `region` | نص \| null | `ipinfo.country` مع اللغة الرسمية الأساسية للإقليم (Babel) | `"en-US"` |
| `language` | نص \| null | اللغة الرسمية الأساسية لـ `ipinfo.country` | `"en"` |
| `ipAddress` | نص \| null | `ipinfo.ip` — عنوان IP العام للجهاز الذي يشغّل SDK | `"192.0.2.10"` |
| `latitude` | رقم \| null | النصف الأول من `ipinfo.loc` — على مستوى المدينة، مشتق من عنوان IP | `37.7749` |
| `longitude` | رقم \| null | النصف الثاني من `ipinfo.loc` — على مستوى المدينة، مشتق من عنوان IP | `-122.4194` |
| `timezone` | نص \| null | `ipinfo.timezone` (اسم IANA) | `"America/Los_Angeles"` |

جميع المفاتيح موجودة دائمًا. قيمة `userAgent` هي دائمًا `"sdk"`؛ وكل مفتاح آخر يكون
`null` عندما لا يوفّره الاستعلام.

هكذا تبدو حمولة التشغيل على الشبكة:

```json
{
  "id": "68d0...",
  "query": "...",
  "executionParams": { "...": "..." },
  "metaData": {
    "userAgent": "sdk",
    "region": "en-US",
    "language": "en",
    "ipAddress": "192.0.2.10",
    "latitude": 37.7749,
    "longitude": -122.4194,
    "timezone": "America/Los_Angeles"
  }
}
```

الإحداثيات تقديرات على مستوى المدينة مستنتجة من عنوان IP. وهي ليست بيانات GPS للجهاز:
لا يطلب SDK الموقع من نظام التشغيل إطلاقًا.

---

## لماذا تُجمع

- **`region` و`language` و`timezone`** — لتنفيذ الوكلاء بما يراعي اللغة والمنطقة. تستخدمها
  المنصة لمواءمة التشغيل مع لغة المستخدم ومنطقته؛ وهذا هو الغرض المعلن من الاستعلام.
- **`userAgent`** — لتمييز حركة SDK عن حركة وحدة التحكم (Console) وواجهة API المباشرة.
- **`ipAddress` و`latitude` و`longitude`** — تُجمع ضمن الاستعلام نفسه وتُرسل مع التشغيل.
  ذُكرت هنا صراحةً بدلًا من إخفائها خلف عبارة عامة، لأن الإفصاح الذي يقلّل من وصف ما
  يغادر جهازك ليس إفصاحًا.

---

## إلى أين تُرسل

وجهتان، تستحق كل منهما ذكرًا منفصلًا:

1. **ipinfo.io** — يُصدر SDK طلبًا واحدًا `GET https://ipinfo.io/json` من الجهاز الذي
   يشغّله. لا يحمل هذا الطلب مفتاح API ولا نص الطلب ولا أي بيانات خاصة بالوكيل؛ لا ترى
   ipinfo.io سوى أن جهازك سأل عن نفسه. راجع
   [سياسة خصوصية ipinfo.io](https://ipinfo.io/privacy-policy) لمعرفة ما تحتفظ به.
2. **الواجهة الخلفية لـ aiXplain** — تُرسل القيم الناتجة داخل حقل `metaData` من حمولة
   التشغيل إلى `BACKEND_URL` (الافتراضي `https://platform-api.aixplain.com`) عبر TLS مع
   مفتاح API الخاص بك. راجع [صفحة الأمان في aiXplain](https://aixplain.com/security/).

---

## متى يحدث ذلك

يُنفَّذ الاستعلام **مرة واحدة لكل عملية Python**، عند أول تشغيل لوكيل، ويُخزَّن مؤقتًا عبر
`functools.lru_cache(maxsize=1)`. وهو محدود بمهلة **ثانيتين**.

هذا يعني أن أول تشغيل لوكيل في العملية قد يكون أبطأ بنحو ثانيتين في البيئات ذات
الخروج الشبكي المقيّد. أما التشغيلات اللاحقة في العملية نفسها فلا تدفع أي تكلفة: تُخزَّن
حالات الفشل أيضًا، لذا يُحاول الاستعلام المحجوب مرة واحدة ولا يُعاد أبدًا.

## عند الفشل

أي فشل — انتهاء المهلة، أو فشل DNS، أو حجب الخروج الشبكي، أو استجابة غير 2xx، أو محتوى
غير قابل للتحليل — يُبتلع ويُسجَّل عند مستوى `DEBUG`. ثم يستمر التشغيل بشكل طبيعي:
يُرسل `metaData` مع `userAgent: "sdk"` وكل الحقول الأخرى `null`. **لا يفشل أي تشغيل
بسبب هذا الاستعلام.**

إذا رأيت `latitude: null` في تتبُّع، فهذا هو السبب.

## أي الاستدعاءات ترسلها

| السطح | موضع الاستدعاء | متى |
|---|---|---|
| v2 `Agent.build_run_payload` | `aixplain/v2/agent.py` | كل تشغيل مباشر لوكيل v2 (`agent.run` / `agent.run_async`) |
| v1 `Agent.run_async` | `aixplain/v1/modules/agent/__init__.py` | كل تشغيل لوكيل v1 (`run` يفوّض إلى `run_async`) |
| v1 `Agent.generate_session_id` | `aixplain/v1/modules/agent/__init__.py` | تهيئة جلسة v1 |
| v1 `TeamAgent.run_async` | `aixplain/v1/modules/team_agent/__init__.py` | كل تشغيل لفريق وكلاء v1 |
| v1 `TeamAgent.generate_session_id` | `aixplain/v1/modules/team_agent/__init__.py` | تهيئة جلسة فريق وكلاء v1 |

تصل تشغيلات وكلاء v2 المباشرة إلى موضع الاستدعاء الوحيد في v2 عبر
`RunnableResourceMixin._post_and_handle_run` الذي يستدعي `build_run_payload`. أما تشغيل
v2 الذي يمرّ عبر جلسة (`agent.run(query, session=…)`) فلا يمرّ بـ `build_run_payload`
إطلاقًا — انظر أدناه.

**وهذه المسارات لا ترسل `metaData`:**

- رسائل جلسات v2 — يرسل `agent.run(query, session=...)` إلى
  `/v1/sessions/{id}/messages` حقول `role` و`content` و`requestId` و`attachments`
  و`tools` فقط.
- تشغيل النماذج وتشغيل خطوط المعالجة (pipelines).
- كل نقطة نهاية ليست تشغيلًا: الإنشاء، والسرد، والبحث، والجلب، والتحديث، والحذف.

## إن لم ترغب في هذا الاستعلام

لا يوجد اليوم خيار في SDK ولا متغير بيئة يعطّله؛ فالمنصة تستخدم هذه الحقول في تنفيذ
الوكلاء، ولذلك فالسلوك مقصود ومفعّل افتراضيًا.

ما يمكنك فعله:

- **حجب الخروج الشبكي إلى `ipinfo.io`** من الجهاز الذي يشغّل SDK. يفشل الاستعلام بعد
  محاولة واحدة مدتها ثانيتان، وتصل الحقول
  `ipAddress`/`latitude`/`longitude`/`region`/`language`/`timezone` بقيمة `null`،
  وتستمر التشغيلات. الخسارة الوظيفية الوحيدة هي استنتاج اللغة والمنطقة — إذ يعود
  الوكلاء إلى الإعدادات الافتراضية للمنصة.
- **تواصل معنا** على [care@aixplain.com](mailto:care@aixplain.com) إن كنت بحاجة إلى
  استثناء تعاقدي أو على مستوى النشر، أو لديك سؤال يتعلق بحماية البيانات بخصوص حقلي
  عنوان IP والإحداثيات.
